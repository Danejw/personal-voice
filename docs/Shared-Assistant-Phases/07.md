# 07 — Learn useful preferences with user control

Branch `shared-memory-assistant` at committed `3267903` (version 0.3.9). Phases 02 through 06 are still uncommitted in this tree. This phase does not start phase 08. None of the migrations was applied to a production project. The `memory-learn` function was not deployed.

Learning is meant to pick up a clear preference from a saved Assistant message after the account opts in, and to leave drafts, quotations, and other people's facts alone. That live check was not run. The rules, the job marker, and the Remembered controls are in tests. The phase is not accepted until the script at the bottom is actually run.

## What changed

- `supabase/migrations/20260930240000_assistant_memory_learning.sql` adds `settings.assistant_memory_learning` (default false) and `settings.assistant_learning_since`. A trigger sets `assistant_learning_since` to `now()` only when the switch goes from off to on. Turning it off does not clear that timestamp. Turning it on again moves the timestamp forward, so the gap and older history are not read.
- The same file allows `assistant_memories.status = 'candidate'` and stores confidence, category, and extractor version `memory-learn-1`. `assistant_memory_jobs` records one row per message, source fingerprint, and extractor version. `list_assistant_learning_batch` returns at most eight finalized user lines saved after the switch, from conversations that are not deleted. `commit_assistant_learning` rereads those rows and writes the memory. `settle_assistant_memory_candidate` keeps or removes a suggestion.
- `src/assistant/memoryLearn.ts` is the fixture gate. The same file is copied to `supabase/functions/memory-learn/memoryLearn.ts`. A clear line such as "I prefer short answers." can become active. "I think I might prefer short answers." and "I prefer tea." stay candidates. Drafts, quotes, hypotheticals, and third-party wording produce nothing.
- `supabase/functions/memory-learn/index.ts` checks the user JWT the same way `text-action` does, calls `gemini-3.5-flash-lite` only to highlight a span, and commits through the RPC. The model's own key and value are not stored. The function is not deployed. If it is missing, the app classifies locally and calls the same commit RPC. The job row stops a repeat from inserting a second memory.
- The Remembered panel has Learn from Assistant. The copy says it reads only saved Assistant messages after the switch, and does not read notes or dictations. Suggestions have Keep and Remove. An extracted active row still uses Forget. Remember, Change, and Forget work while learning is off.
- `docs/SPEC.md` and `docs/ARCHITECTURE.md` now say learning is opt-in and that notes and dictations are not sources.

Dictation, notes, handoffs, settings other than this switch, local device preferences, and `usage_epoch` protection are unchanged. The client does not send `assistant_learning_since`. Microphone audio is still not stored. The live Assistant model stays `gemini-3.8-live`.

## Decisions

- The switch is account settings, off until the user turns it on. Explicit Remember does not require it.
- Only a finalized user line is eligible. Assistant replies, tool rows, interrupted lines, and live microphone chunks are not. A batch is at most eight messages and 2,000 characters each.
- High-precision lines can become active without a confirmation. Uncertain or loose preferences stay candidates and are not sent to a new session.
- An explicit memory is never replaced. A later clear extraction that disagrees becomes a candidate. A later clear extraction may replace an earlier extracted row. The same value is a no-op.
- A forgotten key is not learned again from any conversation. Explicit Remember can still create it.
- A conversation deleted before commit gets a job row and no memory.
- Notes and dictation history are not sources. Syncing dictations is not consent to learn from them.
- Gemini 3.5 Flash-Lite is the existing text model. The permanent key stays in the function. The client never receives it.

## Examples

- "I prefer short answers." With learning on, and the line saved after the switch, the account gets active `answer_length` / `Prefer short answers.`
- "Draft: I prefer short answers." Nothing is stored.
- "I prefer tea." A candidate appears. Keep makes it explicit. Remove forgets it so it is not suggested again.
- An explicit `answer_length` of `Prefer detailed answers.` stays if a later line says "I prefer short answers." That line becomes a candidate. Keep does not overwrite the saved preference.

## Device script

NOT RUN. Do not mark any step passed until it is done on one Android phone and one Windows install, both on the same account, after all five migrations are on the project you mean to use.

1. Leave Learn from Assistant off. Say "I prefer short answers" in Assistant. The Remembered list should not gain that preference. Remember, Change, and Forget should still work.
2. Turn Learn from Assistant on. Say "I prefer short answers" again and wait until the line is saved. The active preference should appear once. Say it again. There should still be one row.
3. Say a drafted or quoted version, such as "Draft: I prefer short answers." It should not create another memory.
4. Say "I prefer tea." A suggestion should appear and should not be sent to a new session until Keep. Remove should leave it forgotten after a restart.
5. Set `answer_length` explicitly to `Prefer detailed answers.` Then say "I prefer short answers." The explicit value should remain. The suggestion should not replace it.
6. Forget a learned key, restart both apps, and say the same fact again. It should not come back. An explicit Remember of that key should still save.
7. Turn learning off and say a new clear preference. It should not be extracted. Turn learning on again and confirm older lines from before this moment are not filled in.
8. Delete a conversation while a line from it could still be learned. The memory from that line should not appear.

## What works now

The account can turn on learning, and a clear saved Assistant line can become a memory without asking every time. Drafts, quotes, and other people's facts are left out. A suggestion can be kept or removed. An explicit preference is not overwritten, and a forgotten one is not learned again. Two devices have not been checked, the learning function has not been deployed, and the live model has not been asked to follow a learned fact.
