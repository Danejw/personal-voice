# 09 — Validate the complete experience

Branch `shared-memory-assistant` at committed `3267903` (version 0.3.9). Phases 02 through 07, the unwired recall files from the unfinished phase 08, and the fixes below are still uncommitted. This pass does not add a product feature and does not start another phase. The assistant migrations are now applied on the VoiceDictationAPP Supabase project this app already uses. The `memory-learn` function was not deployed. The phone, laptop, and desktop journey was not run, so this feature is not accepted for those devices.

## What changed

Sign-out and a new thread could still hand the previous account's attachments or transcript to the next Gemini session. `end()` returns immediately while Assistant is idle, and that is the usual sign-out state. `clearAccountContext()` now always drops the selection, the in-memory screenshot, the saved-transcript seed, and the resume handle, then clears the pending action. Starting a thread, opening another thread, and switching accounts also clear that seed before the next session starts. The thread that finishes loading still seeds its own lines. A continuation package is applied after the clear, so that package is what the new session hears.

The recall ranker fixture now records the other account on that row. The helper had been forcing every row onto the signed-in account, so the suite could not see a cross-account hit. The ranker already drops a different account. The edge-function copy of the learning extractor was rewritten from `src/assistant/memoryLearn.ts` so the two files match again. Line endings had drifted. The extractor rules did not change.

Applying the learning SQL required two corrections in `supabase/migrations/20260930240000_assistant_memory_learning.sql`. A schema-qualified `position(x in y)` does not parse, so those checks use `strpos`. A trailing period on a name or project is removed after the prefix, so "I'm working on the greenhouse." stores `greenhouse`. Those functions were checked on the database: a clear preference is active, a draft is empty, an uncertain line is a candidate, and that project key is `project_greenhouse`.

`src-tauri` is unchanged. Cargo, Clippy, and the Tauri and Android builds were not run.

## What was reviewed and left as it is

Saved conversations, the live Gemini session, explicit and learned memories, the conversation summary, notes and dictations, the analytics profile, and the conversation lease are still separate.

- The transcript lives in `assistant_conversations` and `assistant_messages`. The Gemini socket and its resume handle are not that database.
- Active memories are a separate note. Forgetting one does not delete the conversation. Candidates are not injected. The offline memory cache is keyed by account and is not given to the model.
- The summary is earlier context for one thread. It is not a memory.
- Learning still reads only finalized user lines from Assistant, and only after the account turns it on. Notes and dictations are not learning sources.
- Personal context is the analytics profile for this device. It is not the transcript and not the memory list.
- One device holds the lease. Assistant and tool rows use that fence. Opening a thread does not start the microphone. Continue here is the takeover.

Writes go through security-definer functions that call `assistant_require_account`, with `search_path` empty. `anon` cannot execute them. Authenticated users can execute the account functions and select their own rows. The lease migration dropped the old `append_assistant_message` signature and grants only the fenced one. Assistant does not store microphone audio or screenshot pixels, so this work has no Assistant signed URL. Context sent on a fresh socket stays within 8 recent messages, 6,000 characters of those messages, a 2,000-character summary, and 8,000 characters total. A learning batch is at most 8 messages. The lease lasts 45 seconds and is renewed while that device is answering.

## Decisions

- Phase 08 retrieval stays unwired. The ranker, its tests, the payload parser, and `supabase/migrations/20260930250000_assistant_recall.sql` are in the tree. The app has no `find_saved` tool, no recall settings, and no panel. Wiring that would be a new product surface, and this phase does not add one.
- Shipping this client requires the learning column. `settings` selects `assistant_memory_learning`. It does not select the recall columns, so the recall migration is not required for this build.
- Turning Learn from Assistant off stops new extraction. It does not delete `assistant_memories` or conversations. There is no separate switch that hides saved conversations. Do not drop those tables to turn the feature off.

## Device journey

NOT RUN. Do not mark a step passed from these unit tests.

1. Start a conversation on Android, save a preference and a project decision, and finish a response.
2. Reopen that conversation on the laptop and confirm the transcript and the meaning carry over.
3. Continue on the desktop while the laptop is open. Take over explicitly. The laptop must not write a later assistant line.
4. Start a new conversation. The preference may appear. The previous transcript must not.
5. Correct and forget the preference. Every device, and a fresh or resumed session, must honor that.
6. Retrieve an eligible note, an older dictation, and an old conversation, each with its real source. This step cannot be done until retrieval is connected. See the blocker below.
7. Interrupt a reply, disconnect during save, restart, let the lease expire, and replay a retry. Recoverable user text must remain, and messages must not duplicate.
8. Delete a thread and a memory while another device is offline. After reconnect, neither comes back.
9. Sign out and into another account during an in-flight request. The next account must not see the previous transcript, attachment, lease, or memory.
10. Dictation cleanup, insertion, note save, handoff, dictionary, usage, remote actions, settings, and an older continuation package still work.

`20260930250000_assistant_recall.sql` is applied too. The search function is on the database. This client still does not call it, so retrieval stays off in the app until that tool is connected.

`memory-learn` is optional. The app classifies locally and commits through the RPC when the function is absent. A later deploy, on the confirmed project, with gateway JWT verification off and `GEMINI_API_KEY` already set:

`supabase functions deploy memory-learn --no-verify-jwt`

To stop learning without deleting saved rows, turn Learn from Assistant off. To stop using the feature in the app, sign out or stop opening Assistant. Saved conversations and memories remain until the account deletes them.
